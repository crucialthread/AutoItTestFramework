Function Reference

_TestFmkAssert

Evaluates a condition, records pass or fail, and prints the result to the console.

#include <TestFramework.au3>
_TestFmkAssert ( $bCondition, $sDescription [, $vActual = "" [, $vExpected = "" [, $sScriptName = @ScriptName [, $LineNumber = @ScriptLineNumber]]]] )

Parameters

$bConditionThe condition to evaluate. If True, the assertion passes; if False, it fails.
$sDescriptionA short description of what this assertion is checking. Printed alongside the pass/fail result.
$vActual[optional] The actual value produced by the code under test. Displayed on failure so you can see what the code returned. Strongly recommended.
$vExpected[optional] The expected value. Displayed on failure alongside $vActual. Strongly recommended.
$sScriptName[optional] The name of the test file where the assertion lives. Defaults to @ScriptName.
When the value differs from the currently running script (e.g. when multiple test files are included in a script that includes all test files), the file name is included in the failure output so you can identify exactly which file the failing assertion came from. It is recommended to pass the script name constant declared at the top of each test file.
$LineNumber[optional] The line number of the assertion in the test file. Defaults to @ScriptLineNumber and is included in the failure output for quick navigation to the failing assertion.

Return Value

None.This function does not return a value. Pass/fail state is tracked in internal global counters.

Remarks

Every call to _TestFmkAssert() increments the internal total counter. A passing assertion increments the passed counter and prints a blue [PASS] line. A failing assertion increments the failed counter and prints a red [FAIL] line including the actual value, expected value, file name (when it differs from the running script), and line number.

Always provide $vActual and $vExpected. Without them, a failure only tells you which description failed, not what the actual value was. With them, you can diagnose the failure directly from the console output without re-running the script under a debugger.

Always capture the result of the function under test into a local variable before passing it to _TestFmkAssert(). Calling the function directly inside the assert calls it twice, which can consume extra stub returns or trigger unexpected side effects.

Important: if you are asserting on @error, capture it into a local variable immediately after the call being tested, before passing it to _TestFmkAssert(). Any function call (including _TestFmkAssert itself) resets @error to 0.

Correct: Local $iErr = @error (captured immediately), then _TestFmkAssert($iErr = 1, ...)
Incorrect: _TestFmkAssert(@error = 1, ...) (already reset by the time _TestFmkAssert runs)

Related

_TestFmkHeader, _TestFmkRun, _TestFmkSummary, _TestFmkRunAllTests

Example

#include <TestFramework.au3>

Local Const $MY_TESTS = "MyTests.au3"

Func _TestMyFunc()
    _TestFmkHeader("Test: MyFunc")

    ; Always capture the result before asserting
    Local $iResult = 2 + 3
    _TestFmkAssert($iResult = 5, "2 + 3 equals 5", $iResult, 5, $MY_TESTS)

    ; Asserting on @error - capture it immediately before any other call
    FileRead("nonexistent_file.txt")
    Local $iErr = @error
    _TestFmkAssert($iErr <> 0, "FileRead on missing file sets @error", $iErr, "<> 0", $MY_TESTS)
EndFunc

Func _RunMyTests($bWriteSummary = True)
    Local $bAllPassed = True
	
    $bAllPassed = _TestFmkRun(_TestMyFunc, $bAllPassed)
	
    If $bWriteSummary Then _TestFmkSummary()
    Return $bAllPassed
EndFunc

_TestFmkRunAllTests(_RunMyTests, $MY_TESTS)

Console output (both passing):

+ --- Test: MyFunc ---
> [PASS] 2 + 3 equals 5
> [PASS] FileRead on missing file sets @error

Console output (first assertion failing):

+ --- Test: MyFunc ---
! [FAIL] 2 + 3 equals 5 (actual: 99, expected: 5) [MyTests.au3 - Line: 9]
> [PASS] FileRead on missing file sets @error
