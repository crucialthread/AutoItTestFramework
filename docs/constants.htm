Constants Reference

$TFW_COLOR_*

These constants are single-character prefix strings recognized by SciTE's output pane to color console lines. They are used as the optional $sColor parameter of _TestFmkHeader(), and internally by _TestFmkAssert() and _TestFmkSummary() to color output lines automatically.

$TFW_COLOR_WHITE ":" White (no color highlight). Used for the Failed line when count is zero.
$TFW_COLOR_RED "!" Bold red. Used for [FAIL] lines and the Failed count when non-zero.
$TFW_COLOR_BLUE ">" Blue. Used for [PASS] lines and the Passed count.
$TFW_COLOR_YELLOW "-" Bold yellow. Available for use with _TestFmkHeader() to distinguish test sections visually.
$TFW_COLOR_ORANGE "+" Bold orange. The default color for _TestFmkHeader() and the Total count in the summary.

Remarks

These prefix characters are prepended to the text passed to ConsoleWrite(). SciTE maps each character to a color based on its style.errorlist.* properties. The exact colors rendered depend on the user's SciTE theme/configuration, but the defaults described above match the standard SciTE4AutoIt3 install.

These constants are only meaningful when the script is run from SciTE (via Go/F5 or a Tools menu command). When run from a plain command prompt, the prefix character is printed as a literal character before the text and has no visual significance.

Example

#include <TestFramework.au3>

; Use $TFW_COLOR_YELLOW to distinguish a sub-group of tests visually
_TestFmkHeader("Test: Setup", $TFW_COLOR_YELLOW)

; Use the default orange for the main test group
_TestFmkHeader("Test: Main assertions")

StubConstants.au3

Optional constants for use in test files. Include StubConstants.au3 alongside TestFramework.au3 to use named indexes and parameter name constants instead of raw numbers and strings, making stub calls more readable. 

#include <TestFramework.au3>
#include <StubConstants.au3>  ; optional - named constants for indexes and parameter names
...
Note: Constant names are case-insensitive. $Param_Title and $PARAM_TITLE are equivalent.

Call Index Constants

1-based index constants for use with _SetStubReturn(), _StubCall(), and _GetStubCall().

$_1st1First call index.
$_2nd2Second call index.
$_3rd3Third call index.
$_4th4Fourth call index.
$_5th5Fifth call index.
$_6th6Sixth call index.
$_7th7Seventh call index.
$_8th8Eighth call index.
$_9th9Ninth call index.

An alternative set of ID-style aliases is also available for contexts where the index refers to a control or object ID: $_Id1, $_Id2, $_Id3 ... $_Id9.

Example: 
#include <TestFramework.au3>
#include <StubConstants.au3>
...
	_SetStubReturn("FileExists", $_1st, True) 			; rather  _SetStubReturn("FileExists", 1, True)
	...
	Local $sPath2 = _GetStubCall("FileDelete", $_2nd, $Param_Path) 	; rather  _GetStubCall("FileDelete", 2, $Param_Path)
...

Parameter Name Constants

Named constants for the recorded parameter keys used by stubs. Pass these to _StubCall() or _GetStubCall() instead of raw strings.

Example: 
#include <TestFramework.au3>
#include <StubConstants.au3>
...
	Local $sCopyDest = _GetStubCall("FileCopy", $_1st, $Param_Dest)	; rather  _GetStubCall("FileCopy", $_1st, "sDest")
	
	; Note: $Param_Dest matches any "*Dest" param (i.e: "vDest", "sDest", "dest")
...
Prefix-agnostic matching:
All $Param_* constants work across Hungarian prefix variations. For example, $Param_Default matches both "sDefault" and "vDefault" because _StubCall() and _GetStubCall() fall back to a base name match when an exact key is not found. This means you can use the same constant regardless of the type prefix used by a particular stub. The table below shows the base name pattern each constant matches.
